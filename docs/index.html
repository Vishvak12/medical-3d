medical-3d

A pipeline that builds a 3D point-cloud view of a knee from a left/right pair of clinical X-ray images. It preprocesses the pair, merges it into one image, estimates depth with a pretrained monocular depth model, and back-projects the depth map into a point cloud. The same preprocessing is combined with five different depth models so their output can be compared visually.

Research code. This is not a medical device. The 3D views are relative shape estimates from a single merged 2D image. They have not been validated against ground-truth 3D data or by clinicians, and must not be used for diagnosis.

Pipeline

The five model scripts run the same nine steps. They differ in the depth model (step 7), in output file names, and in the details listed on the reproduce page.

  1. Resize. The right and left image are resized to 256 x 256 (cv2.resize).
  2. Denoise. Bilateral filter, diameter 15, sigma colour 75, sigma space 75 (cv2.bilateralFilter).
  3. Contrast. Brightness-preserving bi-histogram equalization (BBHE) in HSV space, from the image_enhancement package.
  4. Corners. Harris corner response (block size 2, kernel size 3, k = 0.04). Pixels above 1% of the maximum response are painted green.
  5. Merge (D3FFT()). ORB keypoints are matched with a brute-force matcher and the first 20 matches are drawn for inspection. The two resized images are then added pixel by pixel to form the "registered" image.
  6. Channels. The merged image is converted to RGB over a white background (rgba2rgb); pixels that are exactly black become white.
  7. Depth. A pretrained depth model predicts a depth map. The input is resized to dimensions that are multiples of 32 (height at most 480), the prediction is interpolated back bicubically, a 60 px border is cropped, and the result is scaled to 0 to 255.
  8. Point cloud. Open3D builds an RGB-D image and back-projects it with a fixed pinhole camera (focal length 50 px in x and y, principal point at the image centre).
  9. Metrics. Image-quality measures (PSNR, MSE, RMSE, NMSE and others) are written to performance_metrics_*.csv.

Limitations

  • The name "D3FFT" is misleading. D3FFT.py contains no Fourier transform. It matches ORB features and adds two images.
  • No geometric registration. The ORB matches are drawn but never used to estimate a transform, so the two views are not aligned before they are added. The addition is on 8-bit arrays, so sums above 255 wrap around.
  • Harris corners are drawn into the BBHE images before ORB matching, so ORB sees the green markers.
  • Depth is relative. The pretrained depth models are used as downloaded and are not fine-tuned on radiographs in this repository. The camera intrinsics in step 8 are fixed values, not calibrated, so the point-cloud shape is not metric.
  • The metrics do not rank the depth models. They compare the preprocessing stages (steps 2, 3 and 5) against the resized input, so they do not depend on which depth model runs later. See the results page.
  • No quantitative evaluation of the 3D output. There is no ground-truth 3D data, so the renders are shown for visual comparison only.

Data

The clinical knee X-ray data is private and cannot be disclosed. It was received from Dr. Arti Khaparde and Dr. Vaidehi Deshmukh at MIT World Peace University (Dr. Khaparde is no longer affiliated with the university). No X-ray is published here. The renders on the results page are 3D reconstructions rendered from the data.
