Reproduce

The clinical data is private, so you need your own left/right image pairs. The scripts were run on Windows with Python 3.10.14. Nothing here has been tested on Linux or macOS.

Setup

git clone https://github.com/Vishvak12/medical-3d.git
cd medical-3d
pip install -r requirements.txt

Inputs and folders

The scripts use paths relative to the folder you run them from. Create these folders first. cv2.imwrite does not create missing folders.

Dataset And Output/right_test/        your right images
Dataset And Output/left_test/         your left images (same number, same order)
Dataset And Output/Register_img/
Dataset And Output/Register_2D_image/
Original_img/  ABF_img/  BBHE_img/  FeatureDetect_img/  FeatureMatching_img/

Left and right files are paired by position in the folder listing, so the two folders must list in matching order.

Run

From the repository root:

python Models/DepthAnything_V2/depthv2.py

Replace the path with another script from the model table to use a different depth model. The first run downloads the weights from Hugging Face. Outputs go to Dataset And Output/Color_image/ and Dataset And Output/depth_images/, and the metrics go to a performance_metrics_*.csv file in the working folder.

The scripts open interactive windows (Matplotlib with the TkAgg backend, an image viewer, and an Open3D viewer) for every image. Close each window to continue.

Known caveats

  • In the five main scripts the merged images are written to Dataset and Output/Register_img (lowercase "and") and read back from Dataset And Output/Register_img. dinov2.py uses the lowercase form for both. Windows treats these as the same folder; a case-sensitive file system does not.
  • dinov2.py processes the first two pairs (range(0, 2)). The other scripts process every pair in right_test.
  • The scripts are long single files that repeat the same code and have no command-line options. Each model folder carries its own copy of D3FFT.py, channel_conversion.py and performance.py.
